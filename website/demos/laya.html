IV.The decision engine

Not an embedding model, and it writes nothing: a state goes in, a tree of typed questions is answered by one forward pass, every option scored at once. The three types, then three examples — a game loop, an inbox, the smallest round.

Laya answers typed questions about a state — choice, score, noul — in one forward pass, with calibrated probabilities and zero generated tokens.

THE DECISION ENGINE · 1 model · 3 question types · 3 examples · 1 forward pass · 0 input tokens · 0 output tokens

THE THREE TYPES

Its whole vocabulary is three questions. The type decides the criteria you send and the shape you get back; ask any number, in any order, and they are answered together.

choice pick one of N labels

→ one label wins, and every label carries a probability:

score place the state on an ordered scale

→ one position on the scale, plus the distribution over levels:

noul is this true? — with an "I don't know"

→ the probability of true; confidence is distance from a coin flip:

Every answer also carries action.act_probability — a second head reading the same row as act on it or escalate it. It is not part of the question.

THE TREE

A question is a branch. The state is the root, each option is a leaf, and one forward pass scores every leaf — there is no depth-first walk, only one wide read.

the commands this run sent

All four run the sandbox's 32-hidden miniature — random weights, real mechanism; its probabilities are shapes, not judgments. Inbox and Quickstart make one call per round; Snake and Pac-Man make one call per episode and animate locally. Identical requests hit the server's reply cache.

WHAT JUST HAPPENED

One command carried the round: the state as KEYS[1], the questions as ARGV[1]. The preset built each question into its own sequence — instructions first, every option a [MASK] marker, the state at the tail — and sent them as one batch. One pass scored every marker, so the branches came back together.

The bars are the model's probabilities, tempered: the checkpoint's fitted temperature is applied per bucket before the softmax, so confidence — 1 − H(p)/log k — is calibrated, not raw. 0 (0.5 for a yes/no) is a coin flip; 1 is decided. The untrained miniature sits at the floor, which is why the Snake example needs its shield.

WHY IT MATTERS

A classifier zoo is a pipeline of glued-together models; a decision model is one checkpoint and one call. The questions are data — they live in the request, so they diff in review and change without a retrain.

Because every option is scored and the confidence is calibrated, a caller can gate: route at confidence ≥ 0.85, escalate the rest. And the answers are probabilities, not a sentence — nothing to parse, nothing to hallucinate.

THE API

One command, the same for every example. A Laya checkpoint mounts like any scripted model (onnx: + tokenizer: + a preloaded preset); the preset puts the decision on EMB.EVSHA.

model
the mounted checkpoint entry — one per checkpoint you serve.
laya.lua sha1
the preset's digest, preloaded at boot with script_preload.
1
one text: the state.
state · KEYS[1]
a string, or Python-style JSON for a structured state — spaces after every comma and colon, because the checkpoints were trained on exactly those strings.
questions · ARGV[1]
an object of id → {type, instructions, criteria}. Criteria label order is significant — marker order maps to label order — so choice criteria are read in document order.
config · model entry
the checkpoint's envelope, declared on the model's scripts entry and read by the preset as emb.script.config: max_len, head_max_len, min_seq, min_markers, temperature, temperature_by_options. Temperatures outside [0.5, 5.0] clamp; non-numeric values answer with 1.0. An optional ARGV[2] still overrides it per call.

The loop. The Snake preset is a task, not a second command: it declares its own questions and game loop, and one call returns an episode. The host learns nothing about Snake.
