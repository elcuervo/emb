I.The vector

Text becomes a fixed-length list of numbers, and that list is the model's answer — not a hash, and not a rendering of the text.

FIG. 1 — THE VECTOR · — · — dimensions · — weights · float32 reply · 1 536 bytes per vector

WHAT YOU ARE LOOKING AT

A model turns text into a fixed-length list of numbers. That list is the embedding: the model's answer to what does this text mean, expressed as a point. Nothing about it is a hash — the same meaning written two ways lands in nearly the same place, which is the whole reason the rest of this gallery works.

Put a passage below and watch what comes back. The dimension and the byte count are the server's; the preview is the first bytes of the reply itself, so you are looking at the actual value and not a rendering of it. The L2 norm comes from the sandbox's own script, which reports the length of the vector it pooled.

WHAT JUST HAPPENED

Four steps, all of them inside the server: the text is tokenized into the subword units the model was trained on; each token becomes an encoding, a vector that knows its neighbours and its position; the encodings are pooled into one vector — averaged, for these models — and that vector is normalized to unit length. The pooling is what collapses a sentence of any length into one point, and the normalization is why similarity can be a single number: with ‖v‖ = 1, cosine similarity and the dot product are the same thing.

Truncation is the step's own limit. The model reads a bounded number of tokens, so a passage longer than that window loses its tail silently. The sandbox's models are configured for passages, and the corpus this gallery searches was embedded with the same window and the same normalization — the query and the corpus have to go through the same function or the distances mean nothing.

WHY IT MATTERS

Every later plate is this vector plus arithmetic. Similarity is two vectors and a cosine; search is one vector against thousands; a vector store is an index over these points; a classifier is a different graph's answer in the same reply grammar. If the vector is opaque, everything above it is magic — which is why this is plate one.

The bytes matter for the same reason. A vector is 1 536 bytes for these models, not a sentence: an index of a hundred thousand passages is tens of megabytes, and that is a number you can put in a cache, a request, or a browser. The next plate spends that vector on one number.

THE EXACT COMMANDS

Two commands, both shown as the plate issued them. The first asks for the packed bytes; the second calls the sandbox's own preloaded script, which pools and normalizes and reports the dimension and the norm. Neither is simulated. 

EMB minilm BLOB "The thousand injuries of Fortunato I had borne as I best could."
# -> a 1 536-byte bulk string: 384 little-endian float32s

EMB.EVSHA minilm <embed.lua sha1> 1 "The thousand injuries…"
# -> { dim = 384, norm = 1 }
