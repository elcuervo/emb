I.The similarity

Everything retrieval does is this number, sorted. One cosine over two vectors, not 384 additions you have to read.

Two of those lists compare to one score. Sort the scores and you have search.

THE SIMILARITY · — dimensions · one cosine per pair · scripted server-side · no vector on the wire

WHAT YOU ARE LOOKING AT

Two vectors and one cosine. Because the model normalizes its output, cosine similarity is the dot product: 1 is the same direction, 0 unrelated, negative opposed. A paraphrase scores above 0.6; an unrelated passage sits near 0.1.

The sandbox computes the number, not the page: the plate calls a preloaded Lua script by its SHA1 and renders the reply. The source and its digest are printed with it — the sandbox refuses a script it was not told to load.

WHAT JUST HAPPENED

The script calls emb.embed twice — the same path, batcher and cache as EMB — then emb.similarity. It returns one number rather than 768 floats, because the number is the answer.

Doing it in Lua is the product's argument: the arithmetic runs beside the model, over the same packed float32 buffers, so a rerank costs one round trip and no bytes on the wire.

WHY IT MATTERS

Every vector feature is this number. Deduplication, clustering, retrieval, recommendations, anomaly detection: each is a similarity, an ordering, and a threshold chosen for the cost of being wrong. The next plate sorts it over 2 782 passages.

THE EXACT COMMANDS

One command. The count is how many texts the script will see; the reference passage travels as an argument, which keeps the reply cacheable per pair.
