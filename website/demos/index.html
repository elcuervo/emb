The demos gallery

Ten demonstrations of one idea, run against a real server and a real index. The first four answer what is a vector and why does it help; the next five answer why emb — several models, an image in the same space, and a batcher and a cache that make it cheap; and the last is the scripting layer computing structure beside the model. Read them in order, or jump to the one you came for — each stands on its own.

Ten short demos, one idea: text becomes numbers, and numbers let you search by meaning. Every one runs against a real server.

THE READING ORDER

  1. 01 The vector PLATE I · Text becomes 384 numbers, and the vector is the model's answer — not a hash of the text.
    Teaches: the unit everything else is built from. ← start here
  2. 02 The similarity PLATE I · One number between two texts. The whole retrieval story is this number, sorted.
    Teaches: the primitive retrieval is made of.
  3. 03 The search PLATE II · A question phrased in words the corpus never uses, answered with the passages that mean it.
    Teaches: the retrieval step in every RAG pipeline.
  4. 04 The atlas PLATE II · The corpus laid out by meaning. Themes are not a metaphor here — they are regions of a space.
    Teaches: what a vector store actually looks like.
  5. 05 The model lens PLATE III · One corpus, two models, two rankings that do not agree. You cannot mix models.
    Teaches: why shipping more than one embedding is a real decision.
  6. 06 The model is a function PLATE III · One primitive, four answers: bytes, a typed vector, a similarity, a label.
    Teaches: extensibility without forking the server.
  7. 07 The image PLATE III · A photo and eight labels in one space. The model was never trained on these labels.
    Teaches: one space for two modalities; zero-shot tagging.
  8. 08 The batch PLATE III · One call carrying six texts against six calls carrying one each. The model sees one pass, not six.
    Teaches: why embedding a corpus is a job that finishes.
  9. 09 The cache PLATE III · Ask once, ask again. The same vector is memoized, so the repeat is a lookup.
    Teaches: the cheapest speed-up is the one that returns the same answer.
  10. 10 The graph PLATE IV · A Lua script builds the corpus's nearest-neighbour graph beside the model and returns edges, not a matrix.
    Teaches: the scripting layer computing structure in one round trip.

WHAT THESE ARE

Every plate embeds real text with the sandbox's own model, searches a corpus embedded before deployment, and shows the exact command and reply. Nothing is a screenshot and nothing is replayed: where a plate shows a number, it came from the server or the shipped index — and where the sandbox cannot be reached, the plate says so and shows nothing.

The corpus is Poe's collected tales and poems — 86 public-domain works from Project Gutenberg. One author's work has real thematic continents (the sea, the grave, detection, grief), which is what makes a map of the space legible. Your own text answers your request and is not stored or shown to anyone else.

The search runs in your browser over an index built offline and shipped like any other asset, so the sandbox pays one embedding per query. Nothing here writes to the sandbox, and it runs only the scripts it preloaded: EMB.EVAL is refused, on purpose. The cost plates measure the server's own timings, so "cheap" is a reading from the machine, not a claim about it.

Every plate here drives the server. The Ruby client's own surface is its companion on the other side of the wire: the same six texts, four ways of sending them, and the one rule that decides which of the four your call site is already choosing.
