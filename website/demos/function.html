III.The model is a function

One primitive — text in, tensors out — and as many answers as you have scripts. The server runs the scripts it preloaded; it does not run yours.

One model call can hand back bytes, a typed vector, a score or a label. Same model, a different wrapper around it.

WHAT YOU ARE LOOKING AT

emb is not a product with an embeddings endpoint bolted on. It is a server whose primitive is run a model over inputs: one command for the common case, a scripting surface for the rest. This plate runs one passage through four answers, from two models.

The first is the raw command — a bulk string of packed float32s and the metadata the bridge attaches. The next two call the preloaded embed.lua: a typed {dim, norm}, then {dim, norm, similarity} against a reference text. The fourth is classify.lua, whose answer is a label and a confidence.

WHAT JUST HAPPENED


            
Each scripted reply is the server's own bytes. The digest beside it is the SHA1 of the script the server preloaded, and EMB.EVSHA accepts only the digests the sandbox was configured with — so the page cannot describe a script the server does not have.

            
Nothing here sends Lua. EMB.EVAL is refused by the sandbox's allowlist, with the refusal naming the alternative. That boundary is part of the lesson: a public sandbox cannot run a stranger's code, and extensibility does not need it to.



    

    

      

        
WHY IT MATTERS


            
The four answers are four products. A vector store wants the first, a reranker the third, a moderation filter or sentiment badge the fourth. If your server can only return vectors, each is a separate service and a separate deployment — and the models are the expensive part, not the HTTP.

            
Scripting inside the server is also what keeps it fast: the script runs beside the model, over the same buffers, sharing the same batcher and cache, so classify.lua costs one model call and one round trip.



    

    

      

        
THE EXACT COMMANDS


            
Four commands. The three scripted ones name a model and a digest, and the digests are stamped into this page from the script bytes, so they cannot drift from what the sandbox loaded.
